## 2026-03-30 - Scoped CSS collisions when converting interactive spans to buttons in Blazor
**Learning:** In Blazor components, styling forms using broad button selectors like `.login-form button` automatically applies full-width button styles to any new `<button>` added inside input groups (e.g., password toggle icons). Updating form button selectors to `.form-class button:not(.input-icon)` or `.form-class > button` ensures icon buttons retain transparent background and custom sizing while gaining full keyboard navigation accessibility.
**Action:** When replacing `<span @onclick>` icon triggers with `<button type="button">`, always verify CSS scope for generic `button` rules and explicitly add reset styles (`background: transparent; border: none; padding: 0; width: auto; height: auto;`) along with `:focus-visible` indicators.
